What the app is

PoliTricks explains Kenyan bills in English, Kiswahili and Sheng. Every explanation sits beside the clause's official text, and the official PDF's SHA-256 fingerprint is on the page, so a reader can check the AI against the source. It has three parts:

  • A Python pipeline (pipeline/politricks/, command politricks): fetches and fingerprints the official PDFs, cuts them into clauses word for word, asks Claude for explanations, lints them for banned phrases, and walks a human through review.
  • The bill files (src/data/bills/*.json): everything the site shows. Nothing reaches a reader except through these files.
  • An Astro site (src/): prebuilt pages from those files, plus two small live helpers, Match and Explain, that call Claude at request time.

One action, end to end: "what hits me?"

On a bill page, a reader who typed their own words at the welcome screen (for example "I sell mitumba Gikomba") sees the clauses that fit them float to the top, tagged Matches you, with the top three opened.

Reference route (3 stops)

A route to follow in your editor. It is a reference: it was prepared for you, not walked together.

  1. src/pages/bills/[id].astro, search for fetch("/api/match". The page sends the saved words and the bill id. When the answer comes back it adds the matched class, shows the Matches you tag, calls list.prepend(card) for each match and opens the first three. If the call fails or times out, nothing moves: the page stays as it was.
  2. src/lib/api.ts, search for export async function handleMatch. A plain function, so scripts/check-api.mjs can test every status code offline with a stubbed Claude. It answers 400 for an unknown bill or empty words, 502 if the model call fails (and logs why with logUpstream, never the key), and otherwise keeps only ids that exist in this bill, each once, at most MAX_MATCHES (8). The route in src/pages/api/match.ts only turns HTTP into this call.
  3. src/lib/claude.ts, search for async function callMatch. Builds the request: the matcher prompt (pipeline/prompts/matcher.md, the same file the pipeline uses), the bill's English explanations in a cached block, and the reader's words. The answer must parse as a strict schema, or it becomes a 502. The key comes from getSecret("ANTHROPIC_API_KEY") at run time, so a build never contains it.

A practice to reuse: decide the cut before you need it

The decision. On 23 Oct, with 12 slices planned, the build set a cut-off in advance: Sunday 25 Oct, 20:00 EAT. Any slice not done by then gets a recorded cut, and Monday is for shipping only. The kernel it protected is the one in devpost/scope.md under "The Unique Kernel": a clause in Sheng, beside its official text.

The evidence. devpost/checklist.md, Revisions "Deadline and "all 12", 2026-10-23" sets the rule. When slice 8 (What changed) was still blocked on an OCR install at the cut-off, cutting it took one line: "Cut 8". Its code stays merged and tested, the tab shows an honest one-version note, and Monday stayed free for review fixes and shipping (Revisions "Slice 8 cut; slice 7 key and domain in place, 2026-10-25").

On the next project. Write the cut-off and the kernel down on day one, next to the slice list. When the deadline arrives, the question is no longer "can we squeeze it in?" but "is it past the line?", and the kernel says what must still work after anything is cut.
