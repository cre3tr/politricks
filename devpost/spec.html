PoliTricks: how it's built

A Python workshop makes reviewed, fingerprinted content. An Astro shop window serves it as fast, prebuilt pages. Two small live helpers fill the gaps.

Workshop · Python pipeline

Download the official PDF → fingerprint it → pull out the clauses word for word → Claude explains them in EN/SW/Sheng → one JSON file per bill → you review → commit.

Shop window · Astro on Vercel

Pages are built ahead of time from the JSON, so they're light on cheap data. A little JS for toggles and tabs. Your profile and language live on the browser's sticky note.

Source Pipeline Python · pipeline/politricks/

Implements prd.md › Automatic Bill Intake, What It Does, What Changed, Constitution Check (content)

  • Fetch & Fingerprint: official domains only, SHA-256 of the file bytes, stored in sources/.
  • Extract Clauses: pdfplumber plus overrides; every clause verified word for word against the PDF; no OCR.
  • Generate: Claude via Batches, structured outputs (Pydantic), neutral prompt, article numbers validated, refusal fallback on; everything starts as draft.
  • Compare: draft vs draft, bill vs current law (the named Act section), bill vs Act; null marks added or dropped.
  • Civic Data: you type deadlines, channels and challenge avenues from the official notice into civic/<bill>.yaml; Claude only translates.
  • Lint: banned phrases ("unconstitutional", "kinyume cha katiba", "you should"…) and neutrality flags fail the run.
  • Review: walks every draft text (clauses, summary, groups, change notes, civic translations), flagged items first. The Sheng gate.
  • Verify: re-download and compare fingerprints: unchanged / CHANGED / unreachable; --self-test proves it catches a one-byte change.
  • Intake: intake for the first load; intake --check (weekly) only proposes new items from Parliament, Gazette and County listings.

What a hash proves: the build's positive control

A fingerprint proves the text came from this exact file, from this URL, on this date. It doesn't prove "official" beyond the URL's authority. The build proves the checker works by feeding it a one-byte change:

Intact file
verify → unchanged
Same file, one byte altered
verify → CHANGED

Failure modes & fallbacks

Scanned PDFPipeline stops loudly; the bill isn't published.
Model alters clause textVerbatim check fails the run.
Live API down or slowMatch → fixed groups plus a quiet note; Explain → "not ready" state.
Stale participation dataLast checked always shown; over 7 days adds a warning.
Official PDF silently changedVerify flags it, banner on the page, weekly PR.
API spamCaps, ID checks, console spend limit, per-IP limit (best effort).
